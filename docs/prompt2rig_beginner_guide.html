prompt2rig: beginner showcase project (Windows)

Oct 25, 2026.

Source read: mixamorig_stefan/prompt2rig-main (server.mjs, public/.js, hq/, tools/, bench/). Everything below is checked against that code, not just the README.

1. What the system actually is

prompt2rig is "generative mocap": it uses a text-to-video model as a motion prior, then inverts the video back into skeletal animation.

Stage Code What it does
Performer image server.mjs /api/image FLUX.1 schnell on fal makes one neutral full-body person on a plain backdrop. Every clip starts from it (image-to-video), which is what pose estimators like best.
Video server.mjs /api/video fal: MiniMax H3 Max Turbo (480P, ~2-3 s wall) or FLUX 3 Max (720p, ~9 s). Prompt is wrapped in a STAGING clause in app.js (face camera, limbs away from torso, static camera, no cuts).
Live pass public/app.js + retarget.js MediaPipe Pose in the browser, landmarks retargeted to Mixamo bones per frame. Instant, jittery, no GPU needed.
HQ pass hq/worker.py (FastAPI, 127.0.0.1:5178) GVHMR on your GPU: YOLO11m person boxes, ViTPose 2D, HMR2 features, then gravity-aware world-frame SMPL rotations + root translation for the whole clip at once. L/R keypoint-swap stabilizer borrowed from Motion2MixamoRig. Returns axis-angle global_orient, body_pose (21 joints), transl, leg length.
Fingers hq/hands.py WiLoR (needs MANO) or MediaPipe Hands fallback, run in parallel with GVHMR, matched to wrists, rotated into world frame, smoothed.
Retarget public/retarget.js SMPL rotations to Mixamo bones (any T-pose Mixamo .fbx/.glb), live-to-HQ cross-fade.
Export app.js GLTFExporter, /api/takes "↓ glb" writes a skinned animated GLB into takes/ plus a JSON with the source clip URL.
Render tools/render_blender.py Headless Blender: cyclorama, 3-point light, camera arc, optional side-by-side with source clip.
Capture tools/capture.mjs Puppeteer drives headless Chrome, frame-exact 2560×1440 recordings.
Bench bench/ Hand-pose metrics: detection rate, 2D jitter, speed, overlays.

Key idea worth internalising: the live pass is per-frame (no temporal model, so jitter and bone-length drift), the HQ pass is a sequence model with a fixed-proportion body and gravity alignment, so it fixes jitter, limb stretch and forearm twist. The whole UX is built to hide the 4 s HQ latency behind the instant preview.

License trap: the HQ path (GVHMR, SMPL-X, WiLoR, MANO) is non-commercial, YOLO is AGPL. Fine for a personal showcase, not for a product.

2. The beginner project: "Prompt-to-Reel"

Goal: a 30-60 s vertical reel of one Mixamo character performing 4 prompted moves, each shown side by side with the AI source clip, plus a one-page note quantifying live vs HQ quality. It touches every capability: prompt engineering for pose-estimability, both video models, live and HQ retargeting, fingers, GLB export, Blender render.

Built in tiers so you get a result in 15 minutes even before the GPU stack works.

Tier 0: browser only (15 min, no GPU needed)

Prereqs: Node 18+ (winget install OpenJS.NodeJS.LTS), a fal API key with credit.

  1. Open PowerShell in prompt2rig-main.
  2. Create .env (see Windows friction #1 for why not echo >): Set-Content -Path .env -Value 'FAL_KEY=your_key_here' -Encoding ascii
  3. node server.mjs and open http://localhost:5177. The hq pill will say offline; that is expected.
  4. Choose H3 Max Turbo, character X Bot, run preset "does jumping jacks". Watch the MediaPipe live retarget.
  5. Write 4 prompts of your own following the rule in the code: face camera, limbs clear of torso, no spins, flips, floor work or crossed arms. Example set: "mimes a tennis forehand and backhand", "does the Macarena", "conducts an orchestra with big sweeping arms", "counts to five on both hands, holding each number up" (the last one is your finger test).
  6. Load a Mixamo character of your own (mixamo.com, export FBX in T-pose) via "load mixamo file…".
  7. Press "↓ glb" on each take. Files land in takes/.

Tier 1: HQ pass on your NVIDIA GPU (1-2 h, mostly downloads)

Prereqs on PATH: uv (winget install astral-sh.uv), ffmpeg (winget install Gyan.FFmpeg), git (winget install Git.Git; requirements.txt pulls from git+https). Open a new terminal after installing so PATH refreshes.

  1. powershell -ExecutionPolicy Bypass -File hq\setup.ps1 (friction #3). Expect about 5 GB of checkpoints.
  2. Register at smpl-x.is.tue.mpg.de, download SMPL-X v1.1 NPZ, put SMPLX_NEUTRAL.npz in hq\body_models\smplx\.
  3. Optional fingers: register at mano.is.tue.mpg.de, download mano_v1_2.zip, run hq\.venv\Scripts\python hq\setup_hands.py $HOME\Downloads\mano_v1_2.zip (WiLoR checkpoint is 2.5 GB).
  4. Second terminal: hq\.venv\Scripts\python hq\worker.py. Wait for "GVHMR loaded on ...". Reload the browser; the hq pill should show your GPU.
  5. Regenerate your 4 prompts with FLUX 3 Max, "wait for HQ" on, fingers on. Compare to Tier 0 by eye, then export GLBs again.

Tier 2: the reel (30 min)

  1. Install Blender (4.4+; the script handles the 4.4 layered-action API).
  2. Per take: & "C:\Program Files\Blender Foundation\Blender 4.5\blender.exe" -b -P tools\render_blender.py -- takes\<take>.glb --side-by-side (use your real version folder). Use --preview first for a fast look.
  3. Concatenate the four renders\*_compare.mp4 with ffmpeg concat. Done: that is your showcase.

Tier 3 (stretch): measure it, don't eyeball it

Write a ~100-line Python script that loads two exports of the same clip (live vs HQ) and computes per-joint angular jerk (third derivative of rotation, via quaternion log-differences), foot-skate (horizontal foot velocity while foot height is below a threshold) and bone-length variance. Plot them. This turns "HQ looks better" into a number and is the first brick of the bigger project in section 4. bench/hands_bench.py already does the same for fingers (detection rate, 2D jitter): run it with hq\.venv\Scripts\python, not system Python.

3. Windows frictions (found in the code)

  1. .env encoding. server.mjs parses .env as UTF-8 with a line regex. In Windows PowerShell 5.1, echo FAL_KEY=x > .env writes UTF-16LE, the regex never matches, and you get the "FAL_KEY is not set" warning plus failing generations. Use Set-Content -Encoding ascii or Notepad. Also do not quote the value: the parser does not strip quotes, so FAL_KEY="abc" sends the quotes and fal returns 401. A UTF-8 BOM is harmless (JS \s matches U+FEFF).
  2. .env.example is absent in your copy, so the README's cp .env.example .env fails. Just create .env as above.
  3. Execution policy. hq\setup.ps1 is blocked by default (and the zip download carries Mark-of-the-Web). Use -ExecutionPolicy Bypass -File, or Get-ChildItem -Recurse | Unblock-File once.
  4. Silent failures in setup.ps1. $ErrorActionPreference = "Stop" does not stop on a failing native exe (uv, gvhmr.exe) in PowerShell 5.1. Read the output; if any uv pip install errors, the script carries on and the worker fails later with an import error. Rerunning is safe.
  5. GPU generation. setup.ps1 installs torch 2.7.1 from the cu126 index. That covers RTX 20/30/40. An RTX 50-series (Blackwell, sm_120) needs CUDA 12.8 wheels: change the index URL to https://download.pytorch.org/whl/cu128. Update the NVIDIA driver either way.
  6. Long paths. uv building git dependencies can hit MAX_PATH under a deep folder like Downloads\...\mixamorig_stefan\prompt2rig-main. Either move the repo to C:\p2r or enable long paths (admin): New-ItemProperty HKLM:\SYSTEM\CurrentControlSet\Control\FileSystem -Name LongPathsEnabled -Value 1 -PropertyType DWord -Force.
  7. ffmpeg must be on PATH for the worker itself (it resamples every clip to 30 fps with subprocess.run(["ffmpeg", ...])), not just for renders. A winget install needs a fresh terminal.
  8. Hard-coded paths. README uses Blender 5.2; tools/capture.mjs defaults to C:/Program Files/Google/Chrome/Application/chrome.exe (pass --chrome otherwise) and needs npm install first for puppeteer-core.
  9. No NVIDIA GPU: the worker calls CUDA unconditionally (device=0, half=True), so it will not run on CPU or AMD. Tier 0 still works.
  10. Firewall: both servers bind to localhost only, so Windows Defender prompts can be denied safely.

Cost: every generation is a paid fal call (FLUX schnell image once per orientation, then one video per prompt). Check current fal pricing before running stream mode, which generates continuously including idle filler clips.

4. Where to take it (solo-AI project ideas)

  • Closed-loop prompt optimiser. Treat retargetability as a reward: score each take with the Tier 3 metrics plus hand coverage (the worker already returns per-hand coverage), and let an LLM rewrite the prompt to maximise it. Black-box optimisation over the video model's prompt space with a physics-plausibility objective.
  • Physics projection. GVHMR output still foot-skates and floats. Add a post-pass that enforces contact constraints (detect stance frames, pin feet, IK the legs), or track the motion with a physics-simulated humanoid (the PHC / PULSE line of work).
  • Motion library + retrieval. Store every take's SMPL params, embed them, and build "search by motion". You are bootstrapping a synthetic AMASS-style dataset from a video model: video models as world/motion priors.
  • Multi-view consistency. Generate the same prompt from two camera angles with a fixed seed and check whether GVHMR recovers the same 3D motion. Disagreement measures how physically coherent the video model's "imagination" is.
  • Commercial-clean variant. Swap GVHMR/SMPL-X/WiLoR/YOLO for permissively licensed parts (for example MediaPipe + a temporal smoother you train yourself). Distillation from a non-commercial teacher has its own license questions; check them before shipping.
